# ROLE: SENIOR SOLUTION ARCHITECT & PRODUCT MANAGER

Bạn là một **Senior Full-stack Software Architect, Technical Lead, Product Manager và UI/UX Strategist** có kinh nghiệm thiết kế, xây dựng và triển khai các nền tảng web thực tế.

Tôi đang chuẩn bị phát triển một website có tên **Cookora – Bếp Nhà**, nền tảng hỗ trợ khám phá công thức nấu ăn, quản lý thực đơn, tính toán chi phí, dinh dưỡng và hỗ trợ việc nấu ăn hằng ngày.

Tôi đã cung cấp tài liệu mô tả dự án dưới dạng file Word.

**NHIỆM VỤ CỦA BẠN:**

Đọc và phân tích toàn bộ tài liệu được cung cấp, sau đó xây dựng một **MASTER DEVELOPMENT PLAN** hoàn chỉnh, chi tiết, có tính khả thi và đủ rõ ràng để đội ngũ lập trình có thể triển khai dự án thực tế.

## 1. TECHNOLOGY STACK – CÔNG NGHỆ SỬ DỤNG

Tôi muốn sử dụng những công nghệ cốt lõi sau:

**Frontend:**
- React.js
- Tailwind CSS
- JavaScript hoặc TypeScript (đánh giá và lựa chọn)
- Đề xuất các thư viện bổ trợ phù hợp cho routing, state management, form validation, UI components, API communication và biểu đồ.

**Backend:**
- Node.js
- Đánh giá Express.js và NestJS để lựa chọn framework phù hợp.
- Thiết kế RESTful API.
- Xây dựng hệ thống Authentication, Authorization, Business Logic, Validation và Error Handling.

**Database:**
- Microsoft SQL Server là hệ quản trị cơ sở dữ liệu chính.
- Đề xuất ORM hoặc database access layer phù hợp.
- Thiết kế relational database, relationships, constraints, indexes và migrations.

**Infrastructure & Deployment:**
- Docker
- Docker Compose
- Container hóa Frontend, Backend và SQL Server.
- Quản lý môi trường Development, Testing và Production.
- Đề xuất CI/CD, reverse proxy, HTTPS, logging, backup và monitoring.

**AI & Third-party Services:**
- Đánh giá những tính năng thực sự cần AI.
- Đề xuất AI API hoặc mô hình phù hợp.
- Text-to-Speech cho tính năng hướng dẫn nấu ăn bằng giọng nói.
- Nguồn dữ liệu công thức, dinh dưỡng và giá nguyên liệu.
- Giải pháp lưu trữ hình ảnh món ăn.

**Yêu cầu:** Giữ nguyên React, Node.js, Tailwind CSS, SQL Server và Docker làm công nghệ chính. Không tự ý thay thế chúng bằng framework hoặc database khác. Những công nghệ bổ sung phải có lý do rõ ràng, độ ưu tiên, chi phí dự kiến và mục đích sử dụng.

## 2. PRODUCT ANALYSIS – PHÂN TÍCH Ý TƯỞNG

Dựa trên tài liệu Cookora được đính kèm:

1. Phân tích tổng quan ý tưởng và định vị sản phẩm.
2. Xác định bài toán thực tế mà website giải quyết.
3. Phân tích các nhóm người dùng mục tiêu.
4. Xác định Unique Selling Points (USP).
5. Phân tích giá trị khác biệt của Cookora so với các website công thức nấu ăn thông thường.
6. Đánh giá khả năng triển khai và mức độ phức tạp của từng chức năng.
7. Đề xuất cách cải thiện trải nghiệm người dùng.
8. Đề xuất thêm những tính năng có giá trị thực tế nhưng không làm dự án quá phức tạp.

Phân biệt rõ chức năng có sẵn trong tài liệu và tính năng mới do bạn đề xuất.

## 3. FEATURE BREAKDOWN – PHÂN RÃ CHỨC NĂNG

Phân tích chi tiết tất cả các chức năng có trong tài liệu, bao gồm:

1. Recipe Discovery – Khám phá, tìm kiếm và lọc công thức nấu ăn.
2. Cooking Guide – Hướng dẫn nấu ăn theo từng bước, tích hợp giọng nói AI.
3. Có gì nấu nấy – Gợi ý món ăn từ nguyên liệu đang có, tính mức độ phù hợp và nguyên liệu còn thiếu.
4. Serving Calculator – Điều chỉnh khẩu phần và định lượng nguyên liệu.
5. Weekly Meal Planner – Lập thực đơn hằng tuần và tự động tổng hợp danh sách mua sắm.
6. Favorite Recipes – Lưu trữ công thức yêu thích.
7. Eat Fit – Xây dựng thực đơn theo mục tiêu dinh dưỡng.
8. Meal Cost Calculator – Ước tính chi phí món ăn và kiểm soát ngân sách ăn uống.
9. Food Storage Guide – Hướng dẫn bảo quản thực phẩm, quản lý thức ăn thừa và nhắc nhở.
10. Calorie & Nutrition Finder – Tra cứu dinh dưỡng, ghi nhận món đã ăn và theo dõi lượng calories.

Đối với mỗi chức năng, hãy mô tả:
- Mục đích và giá trị đối với người dùng.
- User flow chi tiết.
- Các màn hình cần phát triển.
- Logic xử lý ở Frontend và Backend.
- API endpoints cần thiết.
- Database tables liên quan.
- Công nghệ hoặc thuật toán cần sử dụng.
- Mức độ phức tạp.
- Các trường hợp ngoại lệ và cách xử lý.
- Độ ưu tiên: MVP / Phase 2 / Advanced.

Đặc biệt phân tích logic của tính năng **Có gì nấu nấy**, gộp nguyên liệu vào danh sách mua sắm, tính giá theo khối lượng, quy đổi đơn vị, tính khẩu phần và tính dinh dưỡng.

## 4. SYSTEM ARCHITECTURE – KIẾN TRÚC HỆ THỐNG

Thiết kế kiến trúc tổng thể cho Cookora, bao gồm:

- Frontend architecture.
- Backend architecture.
- Database architecture.
- AI integration architecture.
- File/image storage.
- Authentication & Authorization.
- Docker infrastructure.
- Third-party API integration.

Đề xuất kiến trúc **Modular Monolith** hoặc kiến trúc phù hợp với quy mô dự án, giải thích tại sao nên chọn.

Cung cấp sơ đồ kiến trúc bằng Mermaid, thể hiện toàn bộ luồng:

User → React Frontend → Node.js Backend → SQL Server → AI / External Services.

Phân tích khả năng mở rộng khi số lượng người dùng và dữ liệu tăng lên.

Không đề xuất microservices nếu chưa có lý do thực tế.

## 5. DATABASE DESIGN – THIẾT KẾ SQL SERVER

Thiết kế mô hình cơ sở dữ liệu quan hệ phù hợp cho toàn bộ Cookora.

Bao gồm:
- Danh sách bảng.
- Fields và kiểu dữ liệu SQL Server.
- Primary Keys và Foreign Keys.
- Quan hệ 1–1, 1–N, N–N.
- Unique constraints và indexes.
- Quy tắc chuẩn hóa dữ liệu.
- Những dữ liệu cần lưu lịch sử.
- Entity Relationship Diagram (ERD) bằng Mermaid.

Đặc biệt lưu ý cấu trúc dữ liệu nguyên liệu, công thức, đơn vị đo, khẩu phần, giá thực phẩm, thực đơn, dinh dưỡng và danh sách mua sắm.

Tránh trùng lặp dữ liệu và thiết kế sao cho dễ mở rộng sau này.

## 7. API DESIGN

Thiết kế danh sách REST API cần thiết.

Mỗi API phải có:
- HTTP method.
- Endpoint.
- Mục đích.
- Authentication requirements.
- Request parameters/body.
- Response structure.
- Validation rules.
- Error handling.

Phân chia theo module: Authentication, Users, Recipes, Ingredients, Meal Plans, Nutrition, Budget, Storage, AI và Admin.

Đề xuất tiêu chuẩn API response, pagination, filtering, sorting và versioning.

Đối với dữ liệu dinh dưỡng, an toàn thực phẩm và bảo quản, ưu tiên nguồn dữ liệu đáng tin cậy, thể hiện giới hạn của các kết quả ước tính và tránh để AI tự tạo thông tin thiếu kiểm chứng.
